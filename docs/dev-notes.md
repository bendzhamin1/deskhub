# Заметки по разработке DeskHub

DeskHub — расширение Chrome (Manifest V3), которое заменяет страницу новой
вкладки на рабочий стол с папками и закладками (по механике главной страницы
Яндекс Браузера). Чистый JavaScript, без сборки и зависимостей.

## Структура

- `manifest.json` — MV3, `chrome_url_overrides.newtab` → `newtab.html`,
  разрешения `storage` и `search`.
- `newtab.html` — разметка страницы: строка поиска, сетка карточек, оверлей для
  модалок.
- `css/styles.css` — все стили, светлая и тёмная тема.
- `js/storage.js` — доступ к хранилищу, модель данных, экспорт/импорт, обои,
  кэш иконок. Больше никакой код в `chrome.storage` не лезет.
- `js/newtab.js` — весь интерфейс: рендер, движок иконок, папки, модалки,
  настройки, поиск, drag & drop.
- `assets/` — иконки расширения (16/48/128) и шрифт Inter (вшит локально).
- `design/` — исходник макета. В git не входит (см. `.gitignore`) и в пакет
  расширения не кладётся.

## Модель данных

Состояние: `{ version, settings, cards }`.

- Карточка верхнего уровня — либо `type:"app"` (прямая ссылка), либо
  `type:"folder"` (со списком `items`).
- `settings`: `theme`, `cardSize`, `glow`, `glowIntensity`, `folderOpacity`,
  `showClock`.
- Поля плитки: `title`, `url`, `bg` (цвет подложки), `text`/`tc` (инициалы и их
  цвет), `favicon`. Ручные логотип или цвет помечаются `manual:true` и
  автоопределением не трогаются.
- У папки могут быть свои `color` и `colorAlpha` (0–100).

## Хранилище и синхронизация

Данные лежат в `chrome.storage.sync`, но **режутся на чанки**: JSON состояния
пишется кусками по 6000 символов в ключи `d3:0`, `d3:1`, … плюс мета-ключ
`d3:meta`. Причина: у sync лимит ~8 КБ на один ключ; когда всё лежало в одном
ключе, на 30–40 закладках `set()` молча падал и новые карточки переставали
сохраняться. Чанки поднимают потолок до всей квоты sync (сотни закладок).

- `rawGet` собирает чанки, мигрирует старый одноключевой формат `desktop:v3`,
  поднимает аварийную копию из `chrome.storage.local`.
- `onStateChanged` слушает любой ключ `d3:*` (дебаунс 200 мс) и перечитывает
  состояние — так прилетают правки с другого устройства вживую.
- Синхронизация не требует своего бэкенда и отдельной авторизации: она едет на
  аккаунте Chrome, в который пользователь уже вошёл. Обои хранятся только
  локально (`desktop:wallpaper`) — картинка слишком тяжёлая для квоты sync.

## Поиск (важно для правил Chrome Web Store)

Поиск из строки на новой вкладке выполняется через
**`chrome.search.query({ text, disposition: "CURRENT_TAB" })`** — запрос уходит
в поисковую систему, которую пользователь выбрал по умолчанию в самом Chrome.
Расширение **не задаёт и не меняет** поисковую систему.

- Подсказки строятся **только из своих данных**: введённого запроса, истории
  поиска и своих закладок. Внешние сервисы подсказок не опрашиваются.
- `host_permissions` нет вообще.

**Почему именно так — не откатывать.** Chrome Web Store снимал расширение с
публикации за нарушение правила «одна цель» (single purpose): страница новой
вкладки и персонализация поиска считаются двумя разными функциями. Раньше на
новой вкладке были свой выбор поисковой системы (Google/Яндекс/Bing/DuckDuckGo),
сетевые подсказки Google/DuckDuckGo и поиск по картинке через Google Lens —
именно это и вызывало нарушение. Соответствие правилам достигается тем, что
поиск делегируется системе по умолчанию через Chrome Search API. **Не возвращать**
выбор движка, сетевые подсказки, Lens и host-разрешения к поисковикам — иначе
расширение снова снимут с публикации.

## Разрешения

- `storage` — хранение и синхронизация папок, закладок и настроек.
- `search` — поиск через систему по умолчанию (`chrome.search`).

Больше ничего. `host_permissions` отсутствуют: иконки сайтов грузятся как `<img>`
и разрешений не требуют.

## Движок иконок

Плитка закладки показывает настоящий логотип сайта на его фирменном фоне.

- Единственный источник с CORS — `icon.horse/icon/<domain>`: используется и для
  показа, и для чтения цвета. Один источник → цвет плитки совпадает с
  нарисованным логотипом.
- Цвет (`edgeColor`) — доминирующий по всей площади иконки 32×32; принимается,
  только если один оттенок занимает не меньше 45% площади, иначе плитка остаётся
  нейтральной.
- Фолбэк для показа (без чтения цвета) — Google favicon `s2/favicons?sz=128`
  (CORS не отдаёт, пиксели прочитать нельзя).
- `loadImage` обязан иметь таймаут — без него часть `.ru`-доменов подвешивала
  весь цикл разрешения иконок. Разрешение идёт пулом по 5 параллельно.
- `ICON_VERSION` — гейт: поднять число, и все сохранённые иконки переразберутся
  при следующем открытии вкладки. Найденные логотипы кэшируются как PNG data:URL
  в `chrome.storage.local` (ключ `desktop:icons`).

## Засады страницы новой вкладки

- **`window.prompt` / `alert` / `confirm` на странице новой вкладки заблокированы**
  (молча ничего не делают). Все диалоги — свои DOM-модалки (`openAddModal`,
  `openAppearanceEditor`, `openFolderEditor`, `confirmModal`, `infoModal`).
  Нативные не возвращать.
- **XSS:** строки подсказок и плиток строятся через `textContent` и
  DOM-свойства; `innerHTML` — только для своих константных SVG. Внешние значения
  (названия закладок, URL логотипа от пользователя) через `innerHTML` не
  вставлять.
- **Гонка в `ensureIcons`:** разрешение иконок идёт секундами. Результаты копятся
  патчами по id, и перед сохранением состояние перечитывается заново, иначе
  затираются закладки, добавленные пользователем во время разрешения.

## Экспорт и импорт конфигурации (.cfg)

Обычный JSON с меткой `app:"yandex-desktop-config"`. **Метку не менять** —
по ней проверяются уже выгруженные у людей файлы, смена строки сломает
совместимость (расширение переименовано в DeskHub, но метка осталась прежней).

## Производительность

- Шрифт Inter вшит локально (`assets/fonts/InterVariable.woff2`), без ссылок на
  Google Fonts — быстрее первая отрисовка и работает офлайн.
- Режим `.perf-lite` для слабых машин (память ≤2 ГБ или ≤2 потока) отключает
  размытие фона, крупные тени и hover-анимации; учитывает системную настройку
  «уменьшить движение».
- Часы тикают раз в минуту по границе минуты, а не каждую секунду.

## Локальный просмотр

Нужен HTTP-сервер, потому что страница использует ES-модули (с `file://` не
работает):

```
python3 -m http.server 8755
```

Открыть `http://localhost:8755/newtab.html`. Вне расширения хранилище падает на
`localStorage`, поэтому интерфейс смотрится в обычной вкладке — но чанковую
синхронизацию и `chrome.search` так не проверить: для этого загрузить
распакованное расширение в `chrome://extensions` (режим разработчика →
«Загрузить распакованное расширение» → папка репозитория).

Браузер жёстко кэширует ES-модули: после правок JS убедиться, что сервер отдаёт
свежий файл; при необходимости добавить `?v=N` к `src` скрипта (убрать перед
коммитом).

## Сборка пакета для Chrome Web Store

В zip кладётся: `manifest.json` (в корень архива), `newtab.html`, `README.md`,
`LICENSE` и папки `css/`, `js/`, `assets/`. Папку `design/` и служебные файлы не
включать. Store не принимает повторную загрузку уже опубликованной версии —
номер версии в `manifest.json` поднимать перед каждой заливкой (в остальное
время не трогать).

При отправке новой версии Store требует обоснование каждого разрешения на
вкладке «Меры по обеспечению конфиденциальности», и без нажатия «Отправить на
проверку» черновик в очередь не попадает.
